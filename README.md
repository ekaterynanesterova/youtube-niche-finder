# YouTube Niche Finder

Ищем не «ниши», а **аутлаеры на молодых каналах**: видео, собравшие кратно больше
медианы своего же канала, там, где каналу нет года. Молодой канал + большой выброс =
алгоритм раздаёт трафик формату, а не накопленной аудитории. Это и есть «дверь открыта».

Если выбросы в нише есть только у каналов-миллионников — туда не залететь.

## Что где

```
config/
  seeds.json        — темы-кандидаты. Один seed = одна ниша. Правится руками
  markets.json      — рынки: немецкий (основной) и английский (контроль)
  thresholds.json   — пороги: длительность, бюджеты квоты, что считать выбросом
  policy.json       — правила по темам: где тему не ищем вовсе и где ищем,
                      но помечаем «реклама урезана»
  focus.json        — ниша, которую снимаем сами: за ней следим по суточному
                      приросту и отдаём ей долю поисков в каждом прогоне
src/
  api.js            — клиент YouTube Data API v3
  quota.js          — учёт юнитов с жёстким потолком
  collect.js        — три слоя сбора: разведка → опрос → снапшот
  metrics.js        — выбросы, проницаемость, мусорность
  report.js         — отчёт в markdown
  selftest.js       — проверка счётной части, ключ не нужен
  store.js          — хранилище: упаковка, сжатие, миграция формата
data/               — накопленная база, В GIT НЕ ХРАНИТСЯ (см. ниже)
  channels.json.gz  — каналы
  videos.json.gz    — метаданные видео (только длиннее 8 минут)
  series.json.gz    — дневные срезы просмотров, все одним файлом
  bases.json.gz     — недельные опорные срезы: ВСЕ ролики, включая старые
  current.json.gz   — последние просмотры, лайки, комментарии
reports/
  latest.md         — то же самое текстом, читается прямо на GitHub
index.html          — таблица с сортировкой, живёт на GitHub Pages
```

## Индексация

Сайт закрыт от поисковых машин: в `<head>` стоит `noindex, nofollow, noarchive`,
плюс `robots.txt`. Обход в robots.txt намеренно **не** запрещён — запрет помешал бы
роботу прочитать саму метку `noindex`, и адрес мог бы попасть в выдачу без содержимого.

Это закрывает поиск, но не делает данные секретными: репозиторий публичный,
и всё в нём — включая `docs/` — доступно любому, кто знает адрес.

## Где лежит база

**Не в репозитории.** `data/` стоит в `.gitignore`.

Если заданы секреты `SUPABASE_URL` и `SUPABASE_KEY` — база живёт в Supabase
Storage: прогон скачивает её в начале и заливает изменившееся в конце
(`src/remote.js`). В GitHub тогда не остаётся ни байта собранных данных,
только исходный код и готовая страница. Наших 26 МБ против бесплатного
гигабайта — запас в тридцать восемь раз.

Без этих секретов база уезжает в кэш GitHub Actions: прогон достаёт её шагом
`actions/cache/restore` и кладёт обратно шагом `actions/cache/save`. Копия
каждого прогона висит артефактом две недели — оттуда восстанавливаются, если
кэш выселят. Кэш и артефакт остаются и при включённом Supabase: это тёплый
старт и запасной путь, а первый прогон с Supabase бутстрапится именно из них.

Так сделано не из красоты. Раньше база лежала в git, и каждый ночной прогон
дописывал в историю новый снимок `videos.json` целиком — около ста мегабайт
в сутки, коммитом от бота, по расписанию. 15 сентября 2026 аккаунт за это
заблокировали: правила GitHub запрещают и репозиторий в роли базы данных, и
Actions в роли сборщика данных, а не сборки проекта. Нарушались оба.

Заодно формат переписан. Было 157 МБ, стало 26 — при том, что не потеряно
ни одного ролика: сверка старых и новых метрик дала 8022 совпадения из 8022.
Экономия вся от формата, подробности в шапке `src/store.js`.

В репозиторий уезжает только то, что читает человек: `index.html`, `reports/`,
`docs/` и `config/seeds.json`.

## Что в базе НЕ хранится

Правило простое: поле, которое никто не читает, со временем начинает
выглядеть как данные, и однажды кто-нибудь построит на нём вывод. Поэтому
аудитом убраны:

- `firstSeen` у ролика и у канала — когда мы его впервые увидели. Писалось,
  не читалось нигде. У роликов это было 10,4 МБ.
- `country`, `viaTrending` у канала — записаны, не прочитаны ни разу.
- `id` у ролика и у канала — он же и так ключ записи.
- `uploadsPlaylistId` — всегда `UU` + id без `UC`, проверено на всех 4396
  каналах. Хранится только факт «архив недоступен»: его вывести неоткуда.
- `metrics.json` — собирался «чтобы был», не читался ничем, а после переезда
  базы из git его и забрать стало неоткуда. Всё, что в нём лежало, есть в
  `index.html` и `docs/brief.md`.
- Лайки и комментарии в ДНЕВНЫХ срезах — оттуда читаются только просмотры.
  В `current.json` они остались: по ним считается доля лайков в нише.

## Как продолжить разговор в другом чате

Вся собранная статистика выкладывается одним markdown-файлом:

```
https://raw.githubusercontent.com/ekaterynanesterova/youtube-niche-finder/main/docs/brief.md
```

Он перезаписывается на каждом прогоне и содержит всё, что нужно для разговора с нуля:
принятые ограничения по контенту, свежесть данных, расшифровку метрик, топ ниш с разбором,
таблицы конкурентов, живые заголовки с переводом, архетипы каналов и сравнение рынков.

В новом чате достаточно одного сообщения: «прочитай <ссылка> — это свежая статистика,
дальше работаем по ней». На сайте внизу есть раздел **«Продолжить в другом чате»**
с кнопкой, которая копирует этот запрос целиком.

Файл собирается в `src/brief.js` из того же payload, что и страница, — расходиться
с сайтом ему не с чего.

## Как запустить

Ничего локально ставить не нужно — всё крутится в GitHub Actions.

**Вручную:** вкладка **Actions** → **Сбор данных** → **Run workflow**.
Можно задать `searchBudget` = 0, чтобы не тратить квоту на разведку и только
обновить метрики известных каналов.

**По расписанию:** каждый день в 05:20 UTC, автоматически.

**Смотреть результат:** страница на GitHub Pages (Settings → Pages → Source: Deploy
from a branch, ветка `main`, папка `/ (root)`) или `reports/latest.md` прямо в репозитории.

Нужен один секрет: `YOUTUBE_API_KEY` в Settings → Secrets and variables → Actions.

## Почему так устроено

**API не отдаёт историю просмотров.** Скорость роста нельзя запросить — её можно
только накопить самим. Поэтому ежедневный снапшот, поэтому база копится годами,
поэтому первые недели цифры помечены как ненадёжные.

**Квота 10 000 юнитов в сутки.** `search.list` стоит 100 юнитов, всё остальное — 1.
Разведка съедает почти весь бюджет, поэтому темы прокручиваются по кругу между
прогонами, а не выжигаются за один заход. Счётчик юнитов останавливает прогон
до того, как Google начнёт отдавать ошибки, и уже собранное сохраняется.

**Медиана, а не среднее.** Среднее ломается тем самым выбросом, который мы ищем.
Медиана считается по видео старше 30 дней: свежие ещё не набрали и занижали бы базу.

**Проницаемость считается по каналам, а не по видео.** Один везучий канал с пятью
выбросами не должен давать нише пять очков.

**Шортсы отрезаны жёстко.** Всё короче 8 минут в базу не попадает: шортс с миллионом
просмотров на канале с медианой в три тысячи станет топ-1 выбросом и утопит выдачу.

**Мусорность.** Доля молодых каналов-конвейеров (от 5 видео в неделю, возраст до
полугода) плюс медианная доля лайков на просмотр. Ниша, залитая штампованным
AI-потоком, для нас мертва: YouTube такое давит, а конкурировать объёмом мы не будем.

## Чего софт не умеет

Он не знает про faceless-формат, производственную реализуемость и не предсказывает
будущее. Он показывает, где дверь открыта **сейчас**. Короткий список ниш дальше
проверяется глазами: открыть по пять видео из каждой и решить, собирается ли такое
за день.
